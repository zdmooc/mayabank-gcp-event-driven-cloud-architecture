# C4 Architecture Views

Status: `DESIGNED`.

## C1 — System Context

```mermaid
flowchart LR
  C[Customer] --> M1[Brand A Mobile App]
  C --> M2[Brand B Mobile App]
  D[Dealer / Partner] --> HUB[Maya Financial Relationship Hub]
  CRM[CRM / Customer Legacy] --> HUB
  CS[Contract System] --> HUB
  FS[Finance System] --> HUB
  M1 --> HUB
  M2 --> HUB
  HUB --> AN[Analytics / Architecture Operations]
```

The Hub consolidates synthetic customer/vehicle/contract data, reconciles identities, detects renewal context and serves relationship/recommendation views.

## C2 — Containers

```mermaid
flowchart TB
  APPS[Mobile Apps] --> GW[API Gateway]
  EXT[External mocks] --> GW
  GW --> BFF[Mobile BFF]
  GW --> CORE[Core Domain API services]
  GW --> MATCH[Customer Matching]
  BFF --> REL[Relationship Service]
  CORE --> DB[(Cloud SQL PostgreSQL)]
  MATCH --> DB
  REL --> DB
  CORE --> PS[(Pub/Sub)]
  PS --> MATCH
  PS --> REL
  PS --> ENG[Renewal / Recommendation / Residual Value]
  ENG --> DB
  PS --> AUD[Audit Ingestion]
  AUD --> BQ[(BigQuery)]
```

Logical deployables may initially be consolidated. A bounded context is not automatically one runtime service.

## C3 — Contract processing vertical slice

```mermaid
flowchart LR
  CTRL[ContractController] --> APP[ContractApplicationService]
  APP --> VAL[ContractValidator]
  APP --> REPO[ContractRepository]
  APP --> OUT[DomainEventOutbox]
  REPO --> PG[(PostgreSQL)]
  OUT --> PUB[EventPublisher]
  PUB --> PS[(Pub/Sub)]
  PS --> CONS[Matching / Relationship Consumers]
  CONS --> IDEM[IdempotencyGuard]
```

Implementation may use an outbox or an equivalent transactionally safe publication strategy; ADR will be added when code reaches I5/I13.
